# Dr.Docs

A web application that processes, converts, and repairs files - removing non-password restrictions, converting between formats, merging/splitting PDFs, extracting text via OCR, and normalizing Office documents. Designed for students and faculty who need to batch-process files without bypassing strong encryption or DRM.

---

## Purpose

Users frequently receive files with edit restrictions, sheet protection, or read-only flags that interfere with their work. Dr.Docs provides a single web interface to strip those restrictions, convert files between formats, merge/split PDFs, and extract text - all while respecting strong encryption boundaries.

The project exists because:
- Office files (DOCX, PPTX, XLSX) often have removable editing restrictions applied by authors.
- PDFs can have owner-password restrictions that qpdf can strip without knowing the owner password.
- Batch conversion between formats (Office <-> PDF <-> image) requires infrastructure that is cumbersome to set up per-machine.
- The security boundary is explicit: password-encrypted, DRM-protected, or strongly encrypted files are always rejected with a clear message.

---

## Features

- **Restriction Removal (Unlock)** - Strip editing restrictions from DOCX, PPTX, XLSX; remove owner-password restrictions from PDFs (via qpdf); rebuild ZIP archives without encrypted entries.
- **File Conversion** - Convert between Office formats (DOCX, PPTX, XLSX <-> PDF and many others) via LibreOffice; convert images between JPG, PNG, WebP, AVIF, TIFF, and PDF via sharp.
- **Merge** - Combine PDF, DOCX, PPTX, XLSX, JPG, and PNG files into a single PDF or DOCX output. Non-PDF inputs are transparently converted to PDF first, then merged.
- **Split** - Split a PDF into multiple files by page ranges (e.g. `1-3,5,7-10`) or individual pages.
- **OCR / Text Extraction** - Extract text from PDF, DOCX, PPTX, XLSX, JPG, JPEG, and PNG files using pdf-parse, mammoth, ExcelJS, custom XML parsing, and Tesseract.js OCR.
- **Batch Processing** - Upload and process multiple files simultaneously; all outputs are available as individual downloads or a single ZIP archive.
- **Responsive UI** - Drag-and-drop upload, tool selector, format picker, per-file download links, and status feedback.
- **Security Enforcement** - Rejects password-encrypted files with a clear error; validates MIME types and file extensions; processes files in isolated temp directories; auto-cleans uploads and outputs.
- **Async Task Queue** - In-memory concurrency-limited queue prevents server overload from LibreOffice or qpdf subprocesses.

### Key Directories Explained

- **`client/`** - Single-page React application. All UI code lives in `App.jsx` (no separate component files). Vite proxies `/process`, `/download`, and `/health` to the Express backend during development.
- **`server/`** - Express API. Uses `multer` for file uploads with MIME+extension validation. Routes dispatch to `processService`, which calls the processor router and registers download records. An in-memory queue limits concurrent heavy tasks.
- **`utils/`** - Not an npm workspace; imported directly by the server via relative paths. Contains all file-type detection, validation, and processing logic. The processor `router.js` is the single entry point that delegates to per-format processors.
- **`utils/processors/`** - One module per file type or operation. Each processor receives a file path and returns or writes an output. Processors raise `AppError` for password-encrypted files, corrupt data, or unsupported operations.

## Architecture

### High-Level Design

```
+-------------------------------------------------------------+
|                        Browser                              |
|  React SPA (Vite :5173 / client/dist)                       |
|  Drag-drop files -> FormData -> POST /process                 |
|  Receive downloadId -> GET /download/:id                     |
----------+--------------------------------------+-----------+
           | HTTP (proxy in dev, same-origin in prod)
           ?
+--------------------------------------------------------------+
|                   Express Server (:5000)                     |
|                                                              |
|  POST /process                                               |
|    |-> multer (disk storage + validation)                     |
|    |-> AsyncTaskQueue (max 2 concurrent)                      |
|    |    -> processService.processUploadedFile()               |
|    |        -> utils/processors/router.js::processFile()      |
|    |            -> per-type processor (pdf, office, etc.)     |
|    |        -> downloadStore.setDownloadRecord()              |
|    |    ? { status, results[{downloadId, ...}], batchUrl }   |
|                                                              |
|  GET /download/:id                                           |
|    |-> downloadStore.getDownloadRecord(id)                    |
|    |-> res.download(filePath, downloadName)                   |
|    |-> downloadStore.removeDownloadRecord(id) [on complete]   |
|                                                              |
|  GET /health ? { status: "ok", service: "dr-docs" }   |
--------------------------------------------------------------+
```

### Request/Response Flow

1. The user drops files into the browser drop zone and optionally selects an operation mode, target format, or page ranges.
2. The frontend builds a `FormData` payload and POSTs to `/process`.
3. Express receives the request; `multer` validates MIME+extension and writes files to `server/tmp/uploads/` with UUID filenames.
4. The route handler enqueues the processing task on `AsyncTaskQueue` (concurrency limit: 2).
5. `processService.processUploadedFile()` creates a per-job working directory, calls `router.processFile()` with operation parameters, input file metadata, and binary paths.
6. The router detects each file's type and dispatches to the appropriate processor (PDF, Office, Excel, Image, ZIP, LibreOffice conversion, merge/split, OCR).
7. Each processor reads from the input path, performs the operation, and writes output to `server/tmp/outputs/<processId>_<index>_<name>.<ext>`.
8. After processing, `processService` registers each output in the in-memory `downloadStore` under a random UUID, then returns a JSON response with download IDs.
9. If multiple outputs exist, a batch ZIP archive is also created and registered.
10. The frontend displays individual download links and a "Download All" link.
11. When the user clicks download, `GET /download/:id` streams the file and removes the record (single-use download).
12. A periodic sweep (`startDownloadCleanupScheduler`, every 5 minutes) removes records older than 30 minutes.

### State Management

- **Frontend**: Local React state only (`useState`). No global store. State holds selected files, operation mode, target format, page ranges, processing status, and download results.
- **Backend**: Stateless Express. Download state lives in an in-memory `Map<string, Record>`. The queue state is an in-memory linked list of pending promises.

### Error Handling

- The processor `router.js` and all sub-processors throw `AppError` with a code (`PASSWORD_REQUIRED`, `UNSUPPORTED_FILE`, `FILE_CORRUPTED`, `PROCESSING_FAILED`) and HTTP status code.
- `server/src/middleware/errorHandler.js` catches all errors, normalizes multer errors, and returns a JSON response with a user-facing message and machine-readable code.
- Multer `LIMIT_FILE_SIZE` errors are caught and re-thrown as `AppError` with code `FILE_TOO_LARGE`.
- The frontend displays the error message and reason in a rose-colored status box.
- Files that are strongly encrypted or password-protected receive special handling: the error is always `"This file is securely encrypted and requires the original password."` regardless of the processor.

### Security Model

- **No password bypass**: If a file is password-encrypted or strongly encrypted, the processor detects it (OLE signature, ZIP encryption flag, qpdf error, pdf-lib error, ExcelJS error, mammoth error) and throws `PASSWORD_REQUIRED`.
- **Input validation**: Both extension and MIME type are validated. `application/octet-stream` is accepted as a generic fallback.
- **Path isolation**: Uploads use UUID filenames. Outputs use UUID-based directory names. No user-supplied path components are used in filesystem operations.
- **No execution**: Uploaded files are never executed. They are only parsed by libraries or passed as input to subprocesses (qpdf, soffice) with fixed arguments.
- **Auto-cleanup**: Uploaded files are deleted after processing completes. Outputs are deleted after download or after a 30-minute TTL sweep.

## Core Components

### `utils/processors/router.js`

**Responsibility**: Central dispatcher. Receives operation mode, file list, and options; validates file types; delegates to the correct per-format processor.

**Inputs**: `{ operation, targetFormat, pageRanges, inputFiles[], outputBasePath, workDir, qpdfBin, libreOfficeBin }`

**Outputs**: `{ message, outputs: [{ outputPath, outputExtension, sourceName, outputName, detectedType, message, mimeType }] }`

**Operations dispatched**:
- `unlock` -> `unlockByType()` -> PDF (qpdf), DOCX (JSZip + mammoth), PPTX (JSZip), XLSX (exceljs), ZIP (JSZip + yauzl)
- `convert` -> `convertByType()` -> Images (sharp), everything else (LibreOffice CLI)
- `merge` -> `mergeByType()` -> Convert all inputs to PDF -> `mergePdfFiles()` -> optionally convert merged PDF to DOCX
- `split` -> `splitPdfByRanges()` -> pdf-lib page extraction
- `ocr` -> `ocrByType()` -> OCR per format

### `utils/processors/pdfProcessor.js`

**Responsibility**: Unlock, optimize, and repair PDFs via qpdf CLI.

**How it works**:
- `unlockPdfRestrictions`: Runs `qpdf --decrypt`. If qpdf reports "not encrypted", copies the input to output unchanged. If qpdf reports a password error, throws `PASSWORD_REQUIRED`.
- `optimizePdf`: Runs `qpdf --linearize --object-streams=generate --stream-data=compress`.
- `repairPdf`: Runs `qpdf --linearize`.

### `utils/processors/officeProcessor.js`

**Responsibility**: Unlock DOCX and PPTX restrictions; normalize and repair Office packages.

**How it works**:
- Checks for OLE compound document signature (strong encryption indicator) -> throws `PASSWORD_REQUIRED`.
- Loads the ZIP with JSZip (CRC32 validation enabled).
- For DOCX: removes `<w:documentProtection>` and `<w:writeProtection>` XML elements from `word/settings.xml`. Also validates readability via mammoth.
- For PPTX: removes `<p:modifyVerifier>` and `<p:writeProtection>` from all `ppt/*.xml` files.
- Calls `removeDocProps()` to reset metadata XML templates.
- Calls `validateOfficePackage()` to check for required entries and broken relationship references.
- Rebuilds the ZIP with DEFLATE compression level 9.

### `utils/processors/excelProcessor.js`

**Responsibility**: Remove XLSX sheet protection; optimize and repair workbooks.

**How it works**:
- Loads workbook with `ExcelJS.Workbook.xlsx.readFile()`. If password error is detected, throws `PASSWORD_REQUIRED`.
- Iterates all worksheets and deletes `sheetProtection` from each worksheet model.
- Strips workbook metadata (creator, lastModifiedBy, company).
- Writes output with `workbook.xlsx.writeFile()`.

### `utils/processors/imageProcessor.js`

**Responsibility**: Convert, optimize, and repair images; convert images to PDF.

**How it works**:
- Reads image metadata via `sharp(inputPath).metadata()`. If invalid, throws `FILE_CORRUPTED`.
- Conversion: `sharp` pipeline with format-specific encoding options (JPEG mozjpeg, PNG palette quantization, WebP, AVIF, TIFF LZW).
- Image-to-PDF: embeds the image into a `pdf-lib` `PDFDocument` at its native dimensions.
- Optimization: re-encodes at slightly lower quality (JPEG 80, PNG compression 9).
- Repair: re-encodes at higher quality (JPEG 90, PNG compression 8).

### `utils/processors/zipProcessor.js`

**Responsibility**: Detect encrypted ZIP entries, rebuild normalized ZIP archives.

**How it works**:
- First scans ZIP entries with `yauzl` (low-level parser). If any entry has the encryption bit flag (`0x1`) set, throws `PASSWORD_REQUIRED`.
- If no encrypted entries, loads with JSZip (CRC32 validation) and regenerates.
- Output is a clean ZIP with DEFLATE compression level 9.

### `utils/processors/conversionProcessor.js`

**Responsibility**: Convert files using LibreOffice CLI.

**How it works**:
- Runs `soffice --headless --convert-to <targetFormat> --outdir <dir> <inputPath>`.
- Expects the output file at `<outputDir>/<inputStem>.<targetFormat>` and moves it to `outputPath`.
- 4-minute timeout.

### `utils/processors/mergeSplitProcessor.js`

**Responsibility**: Merge multiple PDFs into one; split a PDF by page ranges.

**Merge flow**:
1. All inputs are converted to PDF (via image processor or LibreOffice).
2. A new `pdf-lib` `PDFDocument` is created.
3. Each input PDF is loaded, pages copied, appended to the merged document.
4. The merged document is saved.

**Split flow**:
1. Page ranges are parsed from a comma-separated string (e.g. `1-3,5,7-10`).
2. Each segment produces a new PDF via `pdf-lib` page copying.
3. Output files are named `<prefix>_part_<N>_page_<X>.pdf` or `<prefix>_part_<N>_pages_<X>-<Y>.pdf`.

### `utils/processors/ocrProcessor.js`

**Responsibility**: Extract text from images and documents.

**Format handlers**:
- JPG/JPEG/PNG -> Tesseract.js OCR worker (English).
- PDF -> `pdf-parse` (text extraction).
- DOCX -> `mammoth.extractRawText`.
- PPTX -> Parse `ppt/slides/slide*.xml` files, extract `<a:t>` text elements.
- XLSX -> Iterate worksheets and rows via `ExcelJS`, tab-separated values.

Output is written as a `.txt` file with normalized whitespace.

### `server/src/services/downloadStore.js`

**Responsibility**: In-memory store for download records with automatic expiration.

- `setDownloadRecord(uuid, { filePath, downloadName, mimeType })` stores a record with `createdAt` timestamp.
- `getDownloadRecord(uuid)` retrieves a record.
- `removeDownloadRecord(uuid)` deletes the record and removes the file from disk.
- `startDownloadCleanupScheduler()` runs a `setInterval` every 5 minutes that sweeps records older than 30 minutes.

### `server/src/services/asyncQueue.js`

**Responsibility**: Concurrency-limited async queue.

- Constructor takes `concurrency` (default 2).
- `add(task)` returns a Promise. The task function is enqueued and executed when capacity is available.
- When a task completes or fails, the next pending task is started.

### `server/src/middleware/upload.js`

**Responsibility**: Multer disk storage with validation.

- Generates UUID filenames: `${Date.now()}-${uuid}${ext}`.
- Validates file MIME type and extension against the supported types in `utils/constants.js`.
- Rejects unsupported files with `AppError("UNSUPPORTED_FILE", 400)`.
- Limits file size to 50MB.

### `server/src/middleware/errorHandler.js`

**Responsibility**: Normalize all errors into a consistent JSON response.

- Multer `LIMIT_FILE_SIZE` -> `AppError("FILE_TOO_LARGE", 400)`.
- Non-AppError -> wrapped in `AppError("PROCESSING_FAILED", 500)`.
- `PASSWORD_REQUIRED` with the encryption message -> preserves the exact message.
- All other codes -> mapped to a short user-facing string.
- Response: `{ status: "failed", message, reason, code }`.

## APIs

### `POST /process`

Main file processing endpoint.

- **Content-Type**: `multipart/form-data`
- **Fields**:
  - `operation` (string, optional, default `"unlock"`): One of `unlock`, `convert`, `merge`, `split`, `ocr`.
  - `targetFormat` (string, optional): Target format extension without dot (e.g. `pdf`, `docx`). Required for `convert` mode. Used for `merge` to choose output format.
  - `pageRanges` (string, optional): Comma-separated page ranges (e.g. `1-3,5,7-10`). Only used in `split` mode.
  - `files` (file, multiple): Files to process. Field name is `files` (supports up to 200 files).
  - `file` (file, multiple): Alternative field name (supports up to 10 files). Both fields are merged.
- **Success Response** (200):
  ```json
  {
    "status": "success",
    "message": "Processed 2 file(s) successfully.",
    "results": [
      {
        "downloadId": "uuid",
        "downloadName": "filename_processed.pdf",
        "downloadUrl": "/download/uuid",
        "detectedType": "PDF",
        "message": "Restrictions removed from PDF."
      }
    ],
    "downloadId": "uuid",
    "downloadName": "filename_processed.pdf",
    "downloadUrl": "/download/uuid",
    "batchDownloadId": "uuid_or_null",
    "batchDownloadName": "unlock_all_processed.zip_or_null",
    "batchDownloadUrl": "/download/uuid_or_null"
  }
  ```
- **Error Response** (4xx/5xx):
  ```json
  {
    "status": "failed",
    "message": "Password required",
    "reason": "This file is securely encrypted and requires the original password.",
    "code": "PASSWORD_REQUIRED"
  }
  ```
- **Error Codes**: `PASSWORD_REQUIRED` (400), `UNSUPPORTED_FILE` (400), `FILE_CORRUPTED` (400), `PROCESSING_FAILED` (500), `FILE_TOO_LARGE` (400)

### `GET /download/:id`

Download a processed file.

- **Parameter**: `id` - UUID returned by `/process`.
- **Response**: File stream with the original `Content-Type` and `Content-Disposition: attachment`.
- **Behavior**: The download record is removed after the response completes (or errors). If the ID is not found or expired, returns 404.
- **TTL**: Records expire after 30 minutes. A background sweep runs every 5 minutes.

### `GET /health`

Health check.

- **Response**: `{ "status": "ok", "service": "dr-docs" }`
- **Status**: Always 200.

## How It Works

### End-to-End Walkthrough

1. **User lands on the home page** - The React SPA renders a header with five tool buttons (Unlock, Convert, Merge, Split, OCR), a drag-and-drop upload zone, and a configuration panel.

2. **User selects an operation** - Clicking a tool button sets the `operation` state. The UI adjusts: "Convert" shows a target format dropdown, "Split" shows a page ranges input, "Merge" shows an output format picker.

3. **User uploads files** - Files are dragged onto the drop zone or selected via a file picker. The frontend validates that each file is <= 50MB. For Split mode, only one file is accepted.

4. **User clicks "Process Files"** - A `FormData` payload is assembled with the operation, optional parameters, and all files. A `POST` request is sent to `/process`.

5. **Express receives the request** - The `multer` middleware validates each file's extension and MIME type against the allowed list. Files are written to `server/tmp/uploads/` with UUID-based names.

6. **The task enters the queue** - The route handler enqueues the processing function on `AsyncTaskQueue` (max 2 concurrent tasks). If other tasks are running, this one waits.

7. **Processing begins** - `processService.processUploadedFile()` creates a unique working directory (`server/tmp/work/<uuid>`) and calls `router.processFile()` with the operation, file metadata, binary paths, and output paths.

8. **File type dispatch** - For each input file, the router detects the file type (extension + MIME) and the operation mode:

   - **Unlock**: PDF -> `qpdf --decrypt`; DOCX -> strip XML protection elements; PPTX -> strip XML modify verifier; XLSX -> delete sheet protection model; ZIP -> scan for encryption, rebuild.
   - **Convert**: Images -> `sharp` pipeline; everything else -> `soffice --headless --convert-to`.
   - **Merge**: All inputs converted to PDF (via `sharp` or `soffice`), then merged with `pdf-lib`, optionally converted to DOCX.
   - **Split**: PDF pages extracted into separate files by page ranges via `pdf-lib`.
   - **OCR**: Text extracted via format-specific parser (tesseract.js, pdf-parse, mammoth, ExcelJS, XML parsing).

9. **Encryption check** - Every processor checks for password protection or strong encryption early. If detected, it throws `AppError("PASSWORD_REQUIRED")` with the exact message: "This file is securely encrypted and requires the original password."

10. **Output registration** - Each successfully processed file receives a UUID download ID. The record `{ filePath, downloadName, mimeType }` is stored in the in-memory download store. If multiple outputs exist, an additional batch ZIP is created and registered.

11. **Response to frontend** - The server returns JSON with download IDs and URLs. The frontend displays individual download buttons and a "Download All" button.

12. **User downloads results** - Each download link calls `GET /download/:id`. Express streams the file and deletes it from disk. The download record is removed - downloads are single-use.

13. **Cleanup** - Uploaded files are deleted after processing (in a `finally` block). The working directory is removed. A background timer sweeps expired download records (>= 30 minutes old) every 5 minutes.

### Security Enforcement Points

- **Upload**: MIME type + extension validation rejects unsupported types.
- **DOCX**: OLE compound document signature check rejects strong encryption.
- **PPTX/XLSX**: Same OLE check.
- **PDF**: qpdf error message parsing detects password-required scenarios.
- **ZIP**: yauzl flag-bit scan detects encrypted entries.
- **All Office**: JSZip CRC32 validation at load time catches corrupt files.
- **All processors**: Explicit `AppError` codes ensure consistent error responses.
